# 个人窗口管理与扩容

入口：**个人 → 窗口管理**（`/windows`）。管理员可在页面下方配置已有签名联动的 Codex2API 渠道、额外额度和费用倍率；用户确认费用后自行开启。

默认关闭；默认额外额度为 5、每个额外窗口的倍率增量为 0.1、倍率上限为 1.5，均可修改。旧策略未保存增量字段时默认使用 0.1，原 `multiplier` 字段作为上限。先部署支持阶梯窗口授权的 Codex2API，并在账号活跃会话容量中设置保留位，再开放 NewAPI 策略。渠道必须已经具有有效的 `CODEX2API_POLICY_BINDINGS` 签名绑定。

新额外窗口的倍率为 `min(倍率上限, 1 + (当前有效额外窗口数 + 1) × 倍率增量)`，保留六位小数。增量允许 0.000001–9，上限大于 1 且不超过 10。增量 0.1、上限 1.5 时，第 1–6 个额外窗口分别为 1.1、1.2、1.3、1.4、1.5、1.5；要创建第 6 个，额外窗口额度也必须至少设置为 6。普通窗口仍为 1 倍。

Codex2API 在用户窗口授权事务内计数、定价，未过期的预留也计入阶梯，重试复用原授权。失效或释放的预留不再占用后续阶梯；已有窗口不随其他窗口数量变化而重新计价。单窗口中途扩容使用同一计算规则。用户确认的是最高倍率，实际价格由授权结果确定，预扣和结算均使用此结果。

普通窗口优先，额外根窗口加价。倍率在窗口创建时固定，预扣和实际结算均使用该倍率；单纯开关扩容不会改变已存在窗口的价格。子请求继承已解析根的档位，不自行创建收费窗口；原有创建冷却、会话锁和模型约束不变。用户提高费用的授权必须再次确认，客户端不能自行传递扩容倍率。

唯一的中途调价入口是个人窗口上的 **保留原账号并扩容此窗口**：普通窗口尚未到期，但原账号普通会话槽已经不足时，用户先开启扩容，再对该窗口单独确认。成功取得原账号保留槽并提交价格后，后续新授权请求立即按新倍率计费；已授权的在途和历史请求保留原价。窗口创建/到期时间、原账号均不变，占用一份个人扩容额度。普通槽仍可复用时不执行不必要的加价；个人额度或账号保留槽不足时不改价、不换号。已扩容窗口不会因关闭总开关自动降价。

`POST /api/user/self/windows/upgrade` 只接受当前窗口的服务池引用、窗口 ID、授权版本 ID 和确认倍率；身份来自登录用户，额度/倍率来自后台策略。服务端重新验证确认价格和授权服务，不接受客户端指定用户或上游账号。升级成功使原价格票据失效，新请求在原服务/原根上重新授权并重算预扣；若其他 NewAPI 进程仍缓存旧票，Codex2API 同样会拒绝旧版本并要求刷新。

窗口页显示普通/扩容状态、创建时间、恢复时间、倒计时，以及创建 CD 的上次评估状态。实际请求时会重新评估创建资格。服务查询失败显示不可用，不视为零使用。各独立 Codex2API 服务池分别统计，不跨库合并额度。

扩容卡片的大号数字显示下一个额外窗口的预计倍率，随窗口列表刷新更新，并排除已过期窗口；步长 0.1 时，没有额外窗口显示 1.1，已有一个显示 1.2，直到达到上限。多个独立服务池的预估不同则显示价格范围，查询失败或列表不完整时不猜测。卡片下方保留步长与上限说明；实际价格仍以创建事务内包含预留窗口的计数为准。

个人查询：每用户短缓存 15 秒，并发查询合并；最多 16 个配置渠道，规范化相同平台/目标去重，4 路网络并发、2.5 秒网络预算，每渠道查找最多 32 个候选密钥。正常续聊使用已校验的窗口授权缓存，不逐次查询后台。

收费授权在预扣前获得并绑定原路由；出现错误返还预扣，不进行跨渠道自动重试。控制查询复用渠道代理，禁止重定向携带凭证。授权本身不会出现在个人查询结果或日志中；用量日志详情仅显示窗口 ID 和收费倍率等非敏感信息。

部署期间保留旧窗口对应的签名绑定/渠道至到期。账号保留容量沿用 Codex2API 原有调度进程的并发边界；同一账号跨多个独立调度进程时仍需要单一所有者或粘性路由，不能把这个功能当作新的分布式账号锁。

阶梯创建与升级使用带签名的 `quote_tiered` / `upgrade_tiered` 控制操作以及 `multiplier_step`。先部署支持这些操作和价格版本验证的 Codex2API，再部署 NewAPI。旧网关会明确拒绝不支持的操作，不能静默退回固定上限价格。Codex2API 仍兼容旧 NewAPI 的固定倍率操作。每次升级只做一次控制请求和当前用户缓存失效，不新增常驻轮询或跨平台全库搜索。
