# Codex2API 上游错误诊断

当渠道已经配置 NewAPI 签名绑定，匹配版本的 codex2api 会通过加密响应头、SSE 注释或 WebSocket 错误字段传回脱敏后的具体错误原因。NewAPI 校验请求、用户、平台、渠道和时间后，移除保护载体，将信息存入日志 `other.admin_info.upstream_error`。无需新增数据库字段。

管理员在日志列表可直接看到具体原因，点击详情可查看错误码、类型、发生阶段、传输方式、实际上游 HTTP 状态及关联请求 ID。普通用户日志不会返回 `admin_info`，原有公开提示和重试规则保持不变。没有实际 HTTP 响应的连接错误显示「未观测到」，不冒充上游 HTTP 500。

先部署 NewAPI，再部署 codex2api，并保持现有签名绑定有效。未绑定、签名错误、超时或成功响应中的诊断都不会被采信。每次重试独立保存诊断，避免上一个失败请求污染后续成功记录。流中途失败时，诊断也可记录在对应的消费日志内。

旧日志已丢失的原始原因无法自动恢复。完整协议说明位于 codex2api 的 `docs/upstream-error-diagnostics.md`；两仓库通过共享固定密文测试报文验证兼容性。
