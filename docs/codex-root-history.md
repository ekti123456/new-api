# Codex 根绑定与无根回溯

## 已确定根的请求

NewAPI 已确定用户根、选中渠道并完成根/Turn/Thread 绑定校验后，不再因为辅助候选历史发布失败而返回 `503 No available channel`。这些历史记录供后续无根请求回溯使用，并不是当前请求的路由授权条件。

发布失败仍记录 `Codex root history publication failed; continuing bound route`，包含用户、Token、模型、请求 ID 和原因。该日志表示辅助历史更新失败，不表示当前主请求已被拒绝。

真正的根绑定冲突、渠道/密钥失效、分组或权限不匹配仍按照原有规则处理；本变更不豁免风控，也不允许关联请求换到其他根。

## 无根请求

依赖历史推断关联的无根请求仍须通过时间范围、作用域、到达先后顺序和别名认领的一致性校验。不能将新到达的根请求当成旧请求的前驱，也不能为了放行覆盖冲突记录。

## 缓存生命周期

- 观察历史容器保留时间按最大允许回溯范围设置，目前为 1 小时；这不是请求等待时间，也不会把实际回溯范围强制设为 1 小时。
- 请求序号容器的保留时间在观察容器基础上增加 10 分钟，目前为 70 分钟；发布或刷新观察记录时同步延长序号容器寿命，不回退已分配的序号。
- 分配新序号时同时核对普通路由和 UA 路由的历史最大序号。即使旧版本的序号缓存已经过期，或者计数器落后于历史，也会从现存历史继续递增，而不是复用仍被占用的编号。
- Redis 使用同一作用域哈希槽内的原子脚本；内存模式在同一互斥锁内完成恢复和分配。不需要通过清空缓存来部署修复。

回归测试覆盖：有根请求遭遇历史冲突或历史服务错误仍可分流、空闲超过 10 分钟后继续请求、计数器缺失/落后的恢复，以及无根时间窗口和真实绑定冲突仍被拒绝。
