# Codex 根绑定与无根回溯

## 已确定根的请求

NewAPI 已确定用户根、选中渠道并完成根/Turn/Thread 绑定校验后，不再因为辅助候选历史发布失败而返回 `503 No available channel`。这些历史记录供后续无根请求回溯使用，并不是当前请求的路由授权条件。

发布失败仍记录 `Codex root history publication failed; continuing bound route`，包含用户、Token、模型、请求 ID 和原因。该日志表示辅助历史更新失败，不表示当前主请求已被拒绝。

真正的根绑定冲突、渠道/密钥失效、分组或权限不匹配仍按照原有规则处理；本变更不豁免风控，也不允许关联请求换到其他根。

## 无根请求

独立后台不再使用“最近记录未命中后普通选号”。没有明确父根时，只从同平台、用户、Token、设备范围的有效主会话候选中选择唯一根；零候选等待，多候选拒绝。不按提示词、模型或账号可用性从多个候选中猜选，也不再用旧的扩展历史前驱兜底放行。当前普通候选成功后保留 30 秒，在途候选保留最多 2 分钟；标题/建议继续要求已有的短期标题候选资格。候选有效期不等于用户窗口寿命。

后台先到时可以等待随后到达的主请求，但必须通过相同范围和唯一候选校验，这属于关联推断，不是伪造历史前驱。原有历史/到达序号仍保留供审计与兼容服务使用。

建立别名后固定主根，并在发布后台 Thread/Turn 映射前完成原子别名认领。Guardian 等有明确父根的请求沿父 Thread 映射找到主根；父绑定缺失、失效或冲突不能转而选择同范围的另一个主请求。已建立的明确关系以用户/根隔离，允许合法令牌轮换；推断新关系才要求同 Token/设备范围。后台不发布主候选，也不创建额外用户/账号窗口。

## 会话内切换模型

已绑定的根渠道不支持新选择的模型时，返回 400 `session_model_unavailable` 并提示新开对话，不再清除原根渠道绑定后跨渠道重试。Codex2API 也在账号层保留当前会话绑定，拒绝不支持的模型，原模型仍可继续使用；新会话重新按目标模型选路。

Codex2API 的同名错误码和提示会原样保留，并强制停止 NewAPI 自动重试。原有被动模型豁免、模型映射和非模型原因导致的不可用恢复规则不变。

## 被动请求的主根等待

- 非 `user` 后台来源统一使用 30 秒等待预算。渠道/根标识可用不代表 Codex2API 的上游账号已绑定：NewAPI 将剩余毫秒数放入签名元数据 `root_account_wait_millis`，Codex2API 不再重新等满 30 秒。
- NewAPI 复用按根/范围的事件通知及每秒缓存检查；同键并发候选查询合并，空结果短暂缓存并在主候选发布时失效。查询范围有界，无全账号扫描或历史用量查询。等待注册有数量限制，客户端取消立即退出。
- Codex2API 在账号/API Key 并发准入之前等待主根账号，同根等待共享缓存查询。后台只沿用确认的主账号，不自行决定主请求用哪个号，不通过重试换号。
- 无法解析的根、冲突的身份或超时返回 400；Codex2API 超时错误码为 `codex_root_account_wait_timeout`，NewAPI 根解析失败为 `codex_background_root_unavailable`。WS 已升级连接使用对应错误帧。主根绑定存在后的模型、账号可用性、权限等限制仍生效。
- 开启用户并发限制时，经过现有身份结构校验的这些后台请求共用每用户最多 2 个独立后台并发位，避免先到的后台请求卡住随后主请求。关闭限制或用户不限并发时保留不限行为；后台请求仍计入当前并发/总并发展示，释放时不占并发冷却。原有窗口创建 CD 不变。
- 签名诊断增加 `original_root_fingerprint`、`root_association`、`root_candidate_count`，分别保留原始根、关联依据和候选数。现有 `root_session_fingerprint` 指向关联后的主根。失败日志也记录关联依据，旧日志不回填。
- 先部署全部 Codex2API 实例，再部署 NewAPI。旧 NewAPI 未关联的独立后台会被新版 Codex2API 明确拒绝；仅升级 NewAPI 无法约束旧 Codex2API 的选号行为。此预算只限制找根/等绑定，不是模型生成时长上限。

## 缓存生命周期

- 观察历史容器保留时间按最大允许回溯范围设置，目前为 1 小时；这不是请求等待时间，也不会把实际回溯范围强制设为 1 小时。
- 请求序号容器的保留时间在观察容器基础上增加 10 分钟，目前为 70 分钟；发布或刷新观察记录时同步延长序号容器寿命，不回退已分配的序号。
- 分配新序号时同时核对普通路由和 UA 路由的历史最大序号。即使旧版本的序号缓存已经过期，或者计数器落后于历史，也会从现存历史继续递增，而不是复用仍被占用的编号。
- Redis 使用同一作用域哈希槽内的原子脚本；内存模式在同一互斥锁内完成恢复和分配。不需要通过清空缓存来部署修复。

回归测试覆盖：有根请求遭遇历史冲突或历史服务错误仍可分流、空闲超过 10 分钟后继续请求、计数器缺失/落后的恢复，以及无根时间窗口和真实绑定冲突仍被拒绝。
