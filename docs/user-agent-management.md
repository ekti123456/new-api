# UA 管理和分流

模型设置中的“UA 分流”现显示为“UA 管理和分流”，原入口、UA 白名单、分组选择和渠道分流逻辑不变。

## 客户端最低版本

默认关闭。开启最低版本限制后，可分别为 `Codex Desktop`、`codex-tui`、`codex_vscode`、`codex_cli_rs`、`codex_exec` 填写最低版本，例如 `0.153.0`。留空表示不限制该类型。

- 设置适用于所有分组，不受 UA 分流开关、分流白名单或用户分流豁免影响。
- 按版本数字比较，不按字符串排序；同一版本的预发布版低于正式版，构建标记不影响比较。
- 已匹配的客户端版本过低、缺失或格式错误时，返回 HTTP 400，错误码 `client_version_unsupported`，提示最低要求和更新 Codex 后重启；不发送重试提示，也不进入选号、回溯等待或模型计费。
- 未配置的客户端、未知 UA 和完全缺失的 UA 不受这些规则影响。UA 可以被客户端修改，这不是不可绕过的身份认证措施。
- `codex_cli_rs` 等引擎 UA 带 `(Codex Desktop;...)` 或 `(codex-tui;...)` 标记时，按对应客户端要求校验引擎版本。
- 使用原始入口 User-Agent，不使用渠道覆盖后的 UA。网关仅判断版本，不自行查询或自动提高最低版本。
- 设置保存为 `user_agent_routing_setting.version_check_enabled` 和 `user_agent_routing_setting.minimum_versions`，与其他设置一起持久化并在重启后恢复。

## 被动模型限制

独立于最低版本开关，具有后台、子代理等被动请求标记的 `gpt-5.4` 请求返回 HTTP 400，错误码 `codex_passive_model_restricted`，提示更新 Codex。即使没有根会话，也在等待根之前拒绝。通过已存储会话关系补全的被动身份会再次检查。

该规则不影响正常用户请求，不自动换模型，也不扩大到 `gpt-5.4-mini`、Luna、Terra 等其他模型。它是本部署的被动调用策略，不是全局模型下架声明。客户端仍可能自行重新发起请求，但网关不会为该拒绝启动重试。
