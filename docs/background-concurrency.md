# 每用户后台请求并发

管理员入口：系统设置 → 安全 → 速率限制 → 每用户后台请求并发上限。

- 选项键：`BackgroundUserConcurrencyLimit`，默认 **5**，允许整数 `1–100000`。
- 使用已有 Option 存储与同步机制，升级时没有该选项则使用默认 5；保存后当前实例的新请求立即使用新值，其他实例按原有配置同步周期更新。
- 后台请求继续按认证用户 ID 使用独立池，同一用户跨模型、会话共同计数，不占普通主请求的并发名额。不改变已有后台分类和父根等待规则。
- 等待主根、执行和流式返回都占用后台名额，整个请求结束即释放，后台不增加并发冷却时间。池满时返回 429 和实际配置的上限，不在该中间件排队。
- 调低上限不会取消已在执行的请求；当前占用降到新上限以下后才继续接纳请求。
- 保留原有开关语义：仅当“启用用户并发限制”开启，且该用户的有效普通并发上限为正时启用后台上限。关闭总开关或该用户配置为不限并发时，不启用此限制。
- 内存与 Redis 模式共用同一配置；普通并发上限、账号粘性、窗口容量与计费规则不变。
