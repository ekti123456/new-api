# 性能错误明细归并

仪表盘的性能错误明细默认按以下字段归并，归并发生在服务端分页之前：

- 用户 ID（不按用户名识别用户）。
- HTTP 状态码。
- 错误类型和错误码。
- 没有错误码时，再按完整错误原因区分，避免把未知错误全部合并。

有错误码时，请求 ID、时间、模型、渠道及错误原因中的动态信息不拆分同一组。
这表示同一种错误码的多次失败，不表示这些请求的正文或错误原因完全相同。
列表展示每组最新请求，末尾数字是当前筛选范围内的发生次数。
点击数字展开逐条原始记录，可再次点击收起；展开明细独立分页、按需加载。
上方同时显示错误分组数和原始错误次数。原始记录不删除，计费、错误统计及请求处理不变。

## 接口

沿用管理员接口 `GET /api/data/performance-errors`：

- `grouped=true`：按组分页。`total` 为分组数，`total_occurrences` 为原始次数。
- 每组包含 `group_key`、`error_group_id`、`occurrence_count`、`first_seen`、`last_seen`；其余字段来自最新请求。
- `error_group_id=<返回值>`：读取指定组的原始请求；必须同时传入列表当前使用的时间、用户、模型等筛选条件。
- 明细以分组查询时最大的记录 ID 为快照上界，不混入查询后写入的记录。刷新列表后可看到新增次数。
- 分组 ID 不存在或不符合筛选时返回空列表；无效 ID 返回 400，不降级为全量查询。
- 不传 `grouped` 或 `error_group_id` 时，保留原来的逐条分页行为。

归并和明细均沿用 48 小时保留范围，以及原有窗口容量错误排除规则。无需修改历史数据或数据库表结构。
