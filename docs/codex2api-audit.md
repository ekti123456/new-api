# Codex2API 审计配置

入口：**系统设置 → 运维 → Codex2API 审计**。配置和连接测试接口仅限超级管理员访问。

## 保存与生效

- 首次保存前，兼容现有 `CODEX2API_POLICY_*` 环境变量。
- 保存后，以数据库中的完整配置为准，覆盖对应环境变量；关闭开关也不会退回环境变量重新启用。
- 当前实例的后续请求立即读取新配置，不需要重启。已在途请求继续使用开始时的配置快照。
- 配置持久保存，重启后仍保留。多实例部署沿用系统既有的配置同步周期。
- 页面显示当前配置来自环境变量还是已保存设置。版本冲突会拒绝覆盖，重新加载后再保存。

## 连接

可添加多条连接，填写 Codex2API URL、平台标识、调用 API Key、现有审计密钥。平台标识和审计密钥须与 Codex2API 对应 API Key 的绑定一致。

调用 API Key 只保存指纹，实际调用密钥仍由渠道管理维护；保存后的连接状态检查从匹配目标地址和指纹的启用渠道中取密钥。URL 可以包含反向代理前缀或 `/v1`。

“测试连接”验证 API Key 和双向签名，不调用模型，也不自动保存表单。状态区显示最近检查时间、结果和延迟。状态查询使用短时缓存，修改配置后的检查使用新的配置版本。

读取配置不会回显已保存审计密钥；留空表示保留原值。更换目标地址或平台标识时需要重新填写审计密钥。页面测试不能绕过 URL / 指纹匹配去借用其他连接的密钥。

## 审计与处罚

可以分别设置：审计连接、签名身份转发、审计记录、违规计次、自动停用账号、自动限制 IP，以及次数阈值和统计窗口。

默认不启用违规计次和自动处罚。只有明确的上游 CYB 决策经过签名验证、被标记为可计次，并且本端开启计次，才会累计；达到阈值后，按账号/IP 开关执行处罚。Codex2API 一侧也需要启用相应 CYB 计次许可。

处罚针对 NewAPI 调用用户。普通 400、普通提示安全拒绝、伪造载荷、重复处罚决定不会新增 CYB 处罚次数；管理员受到既有保护。

## 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/option/codex2api-policy` | 读取脱敏配置、来源及版本 |
| PUT | `/api/option/codex2api-policy` | 带版本保存配置并热更新 |
| POST | `/api/option/codex2api-policy/test` | 测试单条草稿连接 |
| GET | `/api/option/codex2api-policy/status` | 查询已保存连接的状态 |

不要使用通用 option 写入接口修改该配置。它会拒绝直接写入 `Codex2APIPolicySecret`，以保留完整校验和密钥脱敏流程。
