# Codex 无根请求：身份范围与会话前缀

## 路由规则

- 明确的主会话、父线程、祖先 turn 和 fork 关系继续使用完整 ID 绑定，不用前缀替换。
- 无根后台的唯一关联入口是「已认证身份范围哈希 + 原始入站 session_id 前八位」。范围包含平台、NewAPI 用户、令牌、installation ID；不信任客户端自报的 scope_hash。
- 仅接受明确提供、一致的标准 UUID session_id。缺失、冲突、短哈希不能用 thread_id、turn_id、提示词或 prompt_cache_key 补造。
- 同范围可有多个不同前缀，每个前缀索引保存完整主会话 ID。只有一个主会话时才关联；同前缀出现多个主会话时拒绝，即使它们绑定同一个渠道或账号。
- 没有候选时沿用共享主根等待预算（最多 60 秒）；超时返回中文错误，不进入随机、最近账号或模型权重选号。
- 已选主根不可用、指纹变化、分组或 UA 路由不允许时直接报错，不过滤掉该根再寻找另一个根。标题仍保留已命名/命名占用保护。

## 与旧规则的区别

不再使用 5 秒标题窗口、30 秒同范围唯一候选、按到达时间找最近请求或可配置最近账号回退。window_id 的 `:0` 不是推断第一轮的条件。旧设置不能恢复这些路由路径。

所有无根来源使用同一个索引，包括标题、摘要、system、ambient_suggestions、agent_created_thread、memory_consolidation、guardian、subagent 及其他被识别的后台请求。明确父根的压缩沿用准确绑定，不必满足前缀相同。

主根在完整渠道/线程/turn 绑定成功后登记，正常主请求刷新索引。索引最长空闲保留 24 小时，与主根渠道缓存周期一致；原有 Codex2API 永久绑定、会话过期和黑名单拦截不变。单个前缀最多保存 64 个主根，溢出时标记歧义，不能淘汰旧成员制造“唯一候选”。

候选读出后，提交别名还会在 Redis Lua 或内存锁内重新检查唯一性；并发出现第二个主根时停止关联。已经通过本规则建立的别名重试继续使用原主根，不改绑。

## 升级和排查

NewAPI 与 Codex2API 一起更新。NewAPI 查找主根并签名传递；Codex2API 只接受验证后的关联并等待该根账号，不再读写“最近账号”缓存。直连 Codex2API 的无根后台仍然拒绝，不在另一端重新猜测。

别名缓存升级到 v3，旧时间推断别名不迁移。旧的无父 rootless 请求不能绕过新规则读取以前猜出的 thread/自身 turn 绑定；明确祖先绑定仍保留。旧主会话在升级后至少需要一次正常主请求登记新索引，未登记的无根请求会失败，不能用旧时间索引补齐。

诊断 `root_association=scope_prefix_unique` 表示新匹配，`scope_prefix_alias` 表示复用新别名。前缀是 UUID 时间片/分组线索，不是官方父子关系证明：跨前缀的真实附属请求会被拒绝，同前缀单候选也不能保证语义上必然是父根。这是管理员明确启用的确定性推断规则，而非恢复了客户端没有提供的关联信息。
